# Ruler (intellectronica/ruler)

- Repository: https://github.com/intellectronica/ruler
- commit: `cec3dc54d33d53feb256faa7d5e1cde16d0364ec` (2026-11-18)

- In one sentence: concatenates the Markdown rules under `.ruler/` and writes them into the Rule File of each of 30+ coding agents, also syncing MCP config, Skill directories and (experimental) Subagent definitions. It only syncs; it does no evaluation.

Fixed prefix `B=https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec`; all links below are based on this commit.

## Features

| Command | Purpose |
| --- | --- |
| `ruler apply` | Reads `.ruler/`, generates Rule Files for the selected agents, merges MCP config, copies Skills / Subagents, updates `.gitignore`; options include `--agents`, `--nested`, `--backup`, `--skills`, `--subagents`, `--dry-run`, `--mcp-overwrite`, `--gitignore-local` ([commands.ts#L31-L108](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/cli/commands.ts#L31-L108)) |
| `ruler init` | Generates `.ruler/AGENTS.md` and a `ruler.toml` skeleton; `--global` writes to the XDG config directory ([commands.ts#L110-L127](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/cli/commands.ts#L110-L127)) |
| `ruler revert` | Deletes files generated by Ruler and restores from `.bak` ([commands.ts#L129-L175](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/cli/commands.ts#L129-L175), `src/core/revert-engine.ts`) |

**There is no check / lint / verify command.** Validation only happens incidentally when `apply` reads its input (see "Validation" below).

## Architecture and data flow

```
.ruler/AGENTS.md + .ruler/**/*.md + ruler.toml + .ruler/mcp.json
.ruler/skills/<name>/SKILL.md      .ruler/agents/<name>.md
        │ UnifiedConfigLoader / FileSystemUtils.readMarkdownFiles
        ▼
concatenateRules()  ──►  each IAgent.applyRulerConfig()  ──► CLAUDE.md / AGENTS.md / .agent/rules/ruler.md ...
mcp merge          ──►  apply-engine.applyMcpConfiguration ──► .mcp.json / .codex/config.toml ...
SkillsProcessor    ──►  copied to .claude/skills, .agents/skills ...
SubagentsProcessor ──►  .claude/agents/*.md, .codex/agents/*.toml ...
```

- One class per agent, extending `AbstractAgent`; the core methods are `getDefaultOutputPath()` and `applyRulerConfig()` ([AbstractAgent.ts#L18-L58](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/agents/AbstractAgent.ts#L18-L58)).
- Orchestration is in `src/core/apply-engine.ts` (`applyConfigurationsToAgents` starts at L478).

## Core mechanisms

### Source of truth layout

- Searches upward for the nearest `.ruler/` directory, falling back to `$XDG_CONFIG_HOME/ruler` if none is found ([FileSystemUtils.ts#L195-L230](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/FileSystemUtils.ts#L195-L230)).
- `readMarkdownFiles` recursively reads `.ruler/**/*.md`, skipping `.ruler/skills/`; `.ruler/agents/` is also skipped by default. When sorting, `.ruler/AGENTS.md` (or the legacy name `instructions.md`) comes first and the rest are sorted by path; the repository root `AGENTS.md` is also prepended to the front ([FileSystemUtils.ts#L319-L445](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/FileSystemUtils.ts#L319-L445)).
- In `--nested` mode, each subdirectory's `.ruler/` generates its own output (apply-engine.ts L62-L183).

### Sync method

- **Rule File: transform + generate.** All `.md` files are concatenated into one string, each section prefixed with a `<!-- Source: <relative path> -->` comment ([RuleProcessor.ts#L7-L28](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/RuleProcessor.ts#L7-L28)), then written over the target path as a whole file ([AbstractAgent.ts#L38-L58](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/agents/AbstractAgent.ts#L38-L58)). No symlinks.
- **Skill: copy.** Whole directories are copied into each agent's skills directory, and a `.ruler-managed.json` manifest records which entries Ruler manages ([SkillsProcessor.ts#L29](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/SkillsProcessor.ts#L29), [L460-L485](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/SkillsProcessor.ts#L460-L485)).
- **Subagent (experimental, off by default): transform.** Frontmatter of `.ruler/agents/*.md` is converted to each agent's format; Codex gets `.toml` (`SubagentsProcessor.ts` L161, L399-L470).
- **MCP: merge or overwrite.** `[mcp_servers]` in `ruler.toml` is merged with `.ruler/mcp.json` and written to each agent's native config, with key names varying by agent (`mcpServers` / `mcp_servers`) (apply-engine.ts L850-L1080).
- **Hooks: not handled.** The word "hook" appears in the source only in SubagentsProcessor, unrelated to agent hooks.

### Conflict handling

- Before overwriting a Rule File it backs it up to `<file>.bak`. If a `.bak` already exists and carries Ruler's provenance marker, it is kept; if it has no marker, it errors with `Refusing to use existing unverified backup file`. It also writes a `<file>.ruler-generated` provenance marker so revert can tell generated files from user files ([FileSystemUtils.ts#L170-L191](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/FileSystemUtils.ts#L170-L191), [L524-L570](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/FileSystemUtils.ts#L524-L570)).
- Skills: entries with the same name that already exist in the target directory but are not in the manifest are **skipped, not overwritten**, so hand-written user skills are preserved (SkillsProcessor.ts L476-L483).
- On write it rejects symlinks / hard links and paths outside the project root (`assertManagedPathInsideRoot`).

### Validation / check

There is no standalone check command; the following validations all run during `apply`:

- MCP: only checks that `mcpServers` exists and is an object ([mcp/validate.ts#L1-L25](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/mcp/validate.ts#L1-L25)).
- Skill: only a warning when a directory has neither a `SKILL.md` nor sub-skills ([SkillsUtils.ts#L45-L100](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/SkillsUtils.ts#L45-L100)).
- Subagent frontmatter: `name` and `description` are required, `name` must match the file name, `tools`, `model`, `readonly` are type-checked; invalid files are skipped without aborting the whole run ([SubagentsUtils.ts#L38-L120](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/SubagentsUtils.ts#L38-L120)).
- It does not check whether target files are still in sync with the source, i.e. there is no drift detection.

### Version / history

- At load time it computes `contentHash = sha256(content)` for each rule file and `concatenatedHash` for the concatenated result ([UnifiedConfigLoader.ts#L243-L285](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/UnifiedConfigLoader.ts#L243-L285), [hash.ts](https://github.com/intellectronica/ruler/blob/cec3dc54d33d53feb256faa7d5e1cde16d0364ec/src/core/hash.ts#L1-L23)). But grep shows these two values are **not used outside UnifiedConfig and not persisted**.
- No version history of rule or skill files is recorded; there is only one `.bak`.

### Remaining template items

Input / session parsing / Skill trigger detection / grading / baselines / repeated runs / cost: not applicable. Privacy: runs entirely locally, no network access (the repository has no telemetry code).

## Limitations (observed in source)

- The generated Rule File is a concatenation; a Rule Item's origin can only be traced back to its source file via the `<!-- Source: -->` comment, so granularity stops at the file level.
- `.bak` keeps only the first backup, with no history.
- Hashes are computed but not used, so they cannot support drift checks.
- Subagent support is marked experimental and off by default.
